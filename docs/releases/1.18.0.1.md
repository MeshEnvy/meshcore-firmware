# MeshCore 1.18.0.1 USA Cascade

Firmware source: `03214a16df2bd09d3272dfb001d2d322c6740f60`.

USA Cascade defaults are **910.525 MHz, 62.5 kHz bandwidth, SF7 and CR5**.
Saved radio settings take precedence. Choose the exact board, radio, storage
layout and role in the [firmware picker](../firmware_picker.md).

Download the [1.18.0.1 release family](https://github.com/mikecarper/MeshCore/releases/tag/v1.18.0.1-halo-keymind-cascade-dev-03214a16)
and its [migration and bootloader utilities](https://github.com/mikecarper/MeshCore/releases/tag/utility-v1.18.0.1-halo-keymind-cascade-dev-03214a16).
The picker, Mesh America and the Keymind choices in meshfirmware select these
same exact release assets.

## Changes since 1.17.1.9

- Supported nRF52 Repeater and Room Server targets have separate application
  images carrying their exact-board **OTAFIX 2.4.12** bootloader. Ordinary
  applications remain available, together with standalone bootloader files.
- Full Companion includes Meshtext on all supported board families. Message
  retries are bounded; repeated traffic does not become a new local message.
- [ESP-NOW](../espnow_bridge_setup.md) and
  [RS232](../rs232_bridge_setup.md) bridges provide runtime status, counters
  and link probes. The [WiFi UDP bridge](../udp_bridge_setup.md) supports eight
  authenticated IP peers per repeater on an existing station network.
- [Telemetry packet selections](../cli_commands.md#read-repeater-telemetry-history)
  independently control temperature, battery, external I2C voltage, main-radio
  noise and radio2 noise snapshots. All five selections default on; the
  telemetry transmitter itself remains off until enabled.
- Optional [battery forwarding thresholds](../cli_commands.md) can stop repeat
  and flood forwarding independently. Both controls default off; their
  percentages and supported voltage calibration are saved settings.
- Supported radios expose saved `radio.fast` acceleration controls and
  `radio.fast.spi` choices. A `9` MHz selection uses approximately 8.889 MHz
  where the controller supports that rate. Read `get radio.fast.caps` for the
  actual board's options.
- Board profiles consolidate supported display and transport choices, including
  T114 automatic display detection. Exact V4 hardware and storage variants
  remain distinct where their wiring requires a different image.
- T1000-E Companion gives an enumerated USB data connection priority over
  Bluetooth. Bluetooth resumes after USB disconnects if it is enabled;
  battery and a charge-only wall supply allow Bluetooth. Pairing and the saved
  Bluetooth setting are retained.
- Release capacity fixes retain the qualified feature sets with compact help,
  shared buffers and board-specific memory placement. Every image includes its
  own capability and memory reports; capacities still differ between boards.

See [feature controls](../role_feature_switches.md), the
[Full Companion guide](../full_companion_features.md) and
[CLI reference](../cli_commands.md) for supported commands and defaults.

## Choose an installation

For ESP32, the merged `.bin` installs bootloader, partitions and application
over USB. An app-only `.bin` requires a compatible existing partition layout.
When expansion is needed over WiFi or LoRa, use the exact board/role migration
ZIP in this release family's utility page and install its supplied Full
application. Follow the included README; an app-only image cannot expand
partitions. `get storage.layout` reports the live layout where supported.

Ordinary nRF52 UF2 and Serial DFU ZIP files install the application and preserve
the installed bootloader. Repeater, Room Server and Sensor retain separately
qualified **Full supported sensors + LoRa OTA** and
**Reduced sensors + LoRa OTA** choices. These keep the exact OTA target and
storage layout; sensor policy is not a different radio identity.

Separate `with-bootloader-2.4.12` Repeater and Room Server applications carry a
board-matched bootloader. Leave the application powered for at least 70 seconds
after installation. It checks once when radio and OTA activity are idle and
updates a recognized compatible older bootloader; matching current or newer
versions are skipped. Recovery or unrecognized bootloaders require their
documented local migration route. Check `get bootloader.ver` afterward. See
[embedded bootloader installation](../nrf52_embedded_bootloader.md).

The utility release also supplies exact-board bootloader-update UF2,
SoftDevice/bootloader DFU ZIP and SWD HEX files for 23 published OTAFIX profiles
covering 40 hardware aliases. The SoftDevice/bootloader DFU package requires
reinstalling the application. Pending, blocked and retired board mappings are
identified rather than replaced by another board's image.

LoRa OTA reception requires the matching bootloader, target identity, storage
layout and radio settings. Full Companion can send a host-supplied update to
another node; it does not install that LoRa transfer onto itself.

## Verification scope

The complete release has **589 qualified firmware packages**: 435 ordinary
packages and 154 embedded-bootloader variants. The latter cover 77 logical
Repeater/Room targets with both sensor policies. It also includes **69
standalone bootloader files**, **96 exact ESP32 board/role migration packages**
and **26 migration utility builds**.

The completed matrix passed exact target inventory, source provenance,
checksums, packaged OTA identity, native DFU, firmware size, runtime RAM,
sensor-pair, bootloader mapping and migration-layout validation. All 14 jobs in
the [source revision's CI run](https://github.com/mikecarper/MeshCore/actions/runs/40101490838)
passed.

Physical results remain tied to the hardware, revision and installation route
recorded in the [test reports](../test-results/index.md). Building every target
does not establish every board's physical USB, Bluetooth, WiFi, RF, sleep or
update behavior. The release does not qualify every starting firmware or
bootloader migration path.
